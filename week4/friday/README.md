# Week 4 Friday: KijaniKiosk Full IaC Pipeline

Terraform provisions three Ubuntu 22.04 VMs (api, payments, logs) with Multipass (qemu, inside WSL2). `pipeline.sh` turns Terraform's outputs into the Ansible inventory, and Ansible configures every server to the Week 3 standard. State lives in MinIO.

## Runbook (produces every deliverable)

Run everything from `week4/friday/` in WSL.

```bash
# 0. One-time setup: see environment-setup.md
./scripts/start-minio.sh

# 1. First run: creates VMs and configures them
LOG_FILE=pipeline-run1.log ./pipeline.sh multipass

# 2. Challenge E: confirm the state survived. Open http://localhost:9001
#    (minioadmin/minioadmin); bucket kijanikiosk-tfstate should contain terraform.tfstate

# 3. Second run: must show "No changes." and changed=0 on all three hosts
LOG_FILE=pipeline-run2.log ./pipeline.sh multipass

# 4. Checklist: inventory IPs match the live VMs
cat ansible/inventory.ini && multipass list

# 5. Record tool versions, then commit (inventory.ini included)
./scripts/collect-versions.sh

# 6. Tear down
LOG_FILE=destroy-output.txt ./pipeline.sh destroy
```

What each stage does:

- **Stage 0, preflight:** checks the tools are installed and MinIO is reachable.
- **Stage 1, Terraform:** runs `plan -detailed-exitcode`. Exit 0 means nothing to change, so the apply is skipped. Exit 2 means it applies the saved plan.
- **Stage 2, handoff:** checks Terraform and Ansible agree on the SSH key and admin networks, reads each VM's live IP, writes `inventory.ini` atomically, records host keys, and SSH-tests every host.
- **Stage 3, Ansible:** runs the playbook, then totals `changed=` across the PLAY RECAP.

Any failure exits non-zero and names the stage and the command that failed.
